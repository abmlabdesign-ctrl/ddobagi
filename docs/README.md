# 또박 문서함

기획서, 디자인 시안, 참고 자료를 모아 두는 곳입니다. 여기 올린 문서는 팀원과 Claude가 모두 읽고,
작업할 때 기준으로 삼습니다.

| 폴더 | 무엇을 올리나요 | 예시 |
|---|---|---|
| [`planning/`](./planning/) | 서비스 기획서, IA, 정책, 요구사항 | `또박이 서비스 기획서_260820.pdf`, `ia.png`, 요금제 정책 |
| [`design/`](./design/) | 디자인 시안과 디자인 시스템 | `*.dc.html` 시안, `design_system_v1.1_foundations.pdf` |
| [`references/`](./references/) | 참고 자료 | 경쟁 앱 캡처, 사용자 인터뷰, 시장 조사 |
| [`decisions/`](./decisions/) | 결정 기록 | "무료 한도를 하루 1회로 정한 이유" 같은 한 장짜리 메모 |
| [`ai-prompts/`](./ai-prompts/) | AI 공통 지시문 | 대화용·채점용 프롬프트 |
| [`design-handoff.md`](./design-handoff.md) | 개발용 디자인 핸드오프 (기존 문서) | |

## 올리는 방법 (GitHub 웹, 설치 필요 없음)

1. 저장소 페이지에서 왼쪽 위 브랜치 선택 버튼으로 올릴 브랜치를 고릅니다. 보통 `main`입니다.
2. `docs` → 올릴 폴더(예: `planning`)로 들어갑니다.
3. 오른쪽 위 **Add file → Upload files**를 누릅니다.
4. 파일을 끌어다 놓습니다. 여러 개를 한 번에 올려도 됩니다.
5. 아래 **Commit changes**에 무엇을 올렸는지 한 줄로 적고(예: `기획서 v2 업로드`) 버튼을 누릅니다.

폴더째 올리려면 폴더를 그대로 끌어다 놓으면 안의 구조가 유지됩니다.

## 규칙

- **파일 이름에 날짜나 버전을 붙입니다.** `기획서_260820.pdf`, `요금제정책_v2.md`처럼요. 같은 이름으로 덮어써도
  GitHub가 이전 버전을 기록하지만, 이름만 보고 최신을 알 수 있게 하는 편이 편합니다.
- **크기 제한**: 웹 업로드는 파일당 25MB, 저장소는 파일당 100MB까지입니다. 영상처럼 큰 파일은
  Google Drive 등에 올리고 링크만 `references/links.md`에 적어 주세요.
- **비밀 정보는 올리지 않습니다.** API 키, 비밀번호, 개인정보(실명·연락처가 담긴 인터뷰 원본 등)는
  이 저장소에 올리면 안 됩니다. 저장소가 공개라면 누구나 볼 수 있습니다.
- **글로 된 기획은 가능하면 Markdown(`.md`)으로** 써 주세요. GitHub에서 바로 읽히고, 수정 이력이
  줄 단위로 남고, Claude도 가장 정확하게 읽습니다. PDF·이미지도 괜찮습니다.

## 어떤 문서가 기준인가요

내용이 서로 다르면 아래 순서가 우선합니다.

1. `design/`의 `*.dc.html` 시안 — UI의 유일한 기준 (CLAUDE.md "Source of Truth")
2. `planning/`의 최신 기획서 — 기능·정책의 기준
3. `decisions/`의 결정 기록 — 기획서 이후에 바뀐 것
4. `design-handoff.md`
