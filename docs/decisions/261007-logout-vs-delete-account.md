# 로그아웃은 온보딩을 유지하고, 계정 삭제만 초기화한다

- 날짜: 26-10-07
- 상태: 적용됨
- 정한 사람: 기획 요청(계정/온보딩 플로우 1번)

## 배경

로그아웃과 계정 삭제가 같은 동작(`resetOnboarding`)을 불러 기기의 학습자 상태를 전부 지웠습니다.
그래서 로그아웃 후 다시 로그인하면 온보딩(약관 동의 → About you → 마이크 → 레벨 체크)을 처음부터 다시 거쳤습니다.

## 결정

- **로그아웃** — 로그인 상태(`signedIn`)만 끕니다. 온보딩 완료(`onboarded`)와 진행 기록·설정·구독은 기기에 남습니다.
  ON-1에서 다시 로그인하면(Google · Apple · 이메일 모두) 약관 동의와 온보딩을 건너뛰고 바로 홈으로 갑니다.
- **계정 삭제** — 기기의 학습자 상태를 전부 지웁니다. 다음 가입은 ON-1 → 약관 동의 → About you … 처음부터 진행합니다.
- 기능 소개(IN-1 ~ IN-4)는 기존 결정(26-10-01)대로 기기 기준 최초 1회라, 계정 삭제 뒤에도 다시 나오지 않습니다.
- 로그아웃 상태에서는 로컬 알림 스케줄을 비웁니다. 로그인하면 설정대로 다시 잡습니다.

## 이유

로그아웃은 "이 기기에서 잠시 나가기"이고 계정은 그대로이므로, 이미 마친 온보딩을 다시 시키면 안 됩니다.
계정 서버가 없어 기기 저장소가 곧 계정이므로, 로그아웃 때 지우면 다시 로그인해도 돌려받을 수 없습니다.

## 영향

- `src/store/AppStore.tsx` — `signedIn` 추가, `resetOnboarding`을 `logIn` · `logOut` · `deleteAccount`로 분리.
  이전 빌드의 저장 상태는 `onboarded`를 로그인 상태로 간주해 이어집니다.
- `app/index.tsx` — `onboarded && signedIn`일 때만 홈, 아니면 ON-1.
- `app/onboarding/sign-in.tsx` · `email.tsx` — 온보딩을 마친 기기면 로그인 후 바로 홈.
- `app/my/settings.tsx`(Log out) · `app/my/delete-account.tsx`(Delete account).

## 남은 것

- 계정 서버가 없어 어떤 계정으로 다시 로그인했는지 구분하지 못합니다. 로그아웃 후 다른 계정으로 로그인해도
  이 기기에 남은 학습 기록으로 들어갑니다. 인증 서버를 붙이면 서버의 온보딩 완료 여부로 판단하도록 바꿉니다.
